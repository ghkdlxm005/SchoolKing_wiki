# LESSON-0006 — 특정 키만 안 먹히면 코드보다 입력 도달을 먼저 본다

## 규칙

"다른 키는 되는데 이 키만 안 된다"는 증상은 이동·로직 코드를 파기 전에 **그 키가 게임 엔진에 도달하는지**부터 확인한다.

- `UserInputService:IsKeyDown(키)` — 지금 눌려 있다고 엔진이 아는가
- `InputBegan` 발생 횟수 — 그 키의 키다운 이벤트가 실제로 왔는가

둘 다 `false`/`0`이면 코드 문제가 아니다. 입력이 엔진에 닿기 전에 사라진 것이다.

## 입력이 사라지는 흔한 두 원인 (Studio 테스트)

1. **Ctrl 계열 단축키 가로챔** — `Ctrl+W`(탭 닫기) 같은 조합은 Studio가 먼저 먹어 게임에 안 넘어온다. 실제 플레이어 앱엔 그 단축키가 없어 정상 동작한다. → [BUG-0016](../bugs/BUG-0016-crouch-forward-studio-ctrlw.md)
2. **뷰포트 포커스 상실** — Output·Explorer를 클릭하면 게임 화면이 키보드 포커스를 잃어 모든 키가 안 들어온다. 마우스 커서가 보이면(자유 상태) 포커스가 없는 것이다.

## 진단 시 주의

콘솔 로그를 복사하려고 클릭하는 순간 포커스가 빠져서, "안 움직임"이 재현된 것처럼 오인된다. 상태는 **화면 GUI로 띄우거나**, 키가 눌린 순간의 로그만 남기는(키다운 필터) 방식으로 확인한다.
