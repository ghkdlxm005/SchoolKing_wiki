# LESSON-0007 — 1인칭 뷰모델 벽 관통 해결: 세 방법과 함정

## 문제

1인칭 뷰모델(총)이 벽에 붙으면 벽을 뚫고 보인다. 해결책은 셋인데 각각 대가가 다르다.

| 방법 | 벽 관통 | 대가 |
| --- | --- | --- |
| ViewportFrame | 완전 차단 | 월드 조명·그림자·**파티클을 못 씀**. 총이 평면처럼 보임 |
| 모델 축소(shrink) | 줄어듦 | CFrame/FakeCamera 기반 뷰모델엔 적용이 까다롭고, 너무 작으면 근접 클리핑 |
| 레이캐스트 오프셋(retract) | 완화 | 비스듬히 바짝 붙으면 살짝 보일 수 있음. 그 외 전부 정상 |

## ViewportFrame이 함정인 이유

"영상에서 본 그 방식"이라 끌리지만, ViewportFrame은 **월드와 분리된 별도 렌더**다. 그래서:

- **월드 조명·그림자·동적 조명을 못 받는다.** 자체 평면 조명(Ambient/방향광)만. 태양 방향을 흉내내도 여전히 "그림"처럼 보인다.
- **ParticleEmitter를 아예 렌더하지 않는다.** 총구 연기·차징 화염 등 파티클 기반 이펙트가 통째로 사라진다. 파트로 하나씩 재구현해야 하는데 작업량 대비 품질이 나쁘다.
- 뷰모델을 WorldModel로 옮기면 기존 정리 로직(카메라 자식 기준)이 못 찾아 잔존한다.

DevForum 정설도 같다 — "ViewportFrame 쓰지 마라. 환경 조명을 잃는다."

## 모델 축소가 어려운 이유

축소는 총을 월드에 두면서 작게·가깝게 만들어 벽에 안 닿게 한다(조명·파티클 유지). 하지만:

- 이 프로젝트 뷰모델은 **FakeCamera 기준으로 위치**를 잡는다. `ScaleTo`는 PrimaryPart 기준이라 둘이 어긋나 이중 스케일·오정렬이 난다.
- 너무 작게 하면 카메라 근접 클리핑으로 안 보인다(긴 무기일수록 딜레마).

## 결론 — retract

레이캐스트로 전방 벽을 감지해 뷰모델 전체를 카메라 쪽으로 당긴다(`Model:PivotTo`). 총이 월드에 그대로라 조명·그림자·파티클이 전부 정상이고, 벽은 최대한 막는다. 완벽하진 않지만 유일하게 다른 요구와 충돌하지 않는다.

주의: 뷰모델 파트는 앵커된 루트에 웰드돼 있어 **루트 CFrame만 옮기면 같은 프레임 렌더에 반영이 안 된다**(웰드는 물리 단계에서 풀림). 반드시 `Model:PivotTo`로 모델 전체를 옮긴다.

## 적용 대상

- 1인칭 뷰모델을 카메라 자식으로 두고 매 프레임 배치하는 모든 무기
- "영상처럼 벽 안 뚫게" 요구가 들어올 때 — ViewportFrame으로 가기 전에 이 표를 먼저 본다
