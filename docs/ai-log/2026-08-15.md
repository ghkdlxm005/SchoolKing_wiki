## 1. Dustpan 뷰모델 "축 고정" 버그 (핵심)

- **증상**: 쓰레받이가 손에 박힌 채, 애니를 재생해도 회전(축 이동)하지 않음. 사용자가 리그·애니는 다 맞춰뒀고 "코드의 무언가" 때문이라고 지목.
- **진단 경위**: 처음엔 애니 코드로 포즈를 잡으려다(강제 IdleAnim·마지막 프레임 freeze·달리기 시퀀스) 오히려 리그 기본 포즈를 덮어써서 헤맴 → 전부 원복해도 여전히 박힘 → **애니가 아니라 리그 조인트가 잠긴 것**으로 방향 전환. Compass(정상 무기)와 비교: Compass는 idle 애니 없이 리그 기본 포즈로 잘 잡힘 → Dustpan도 리그 기본이 정상이어야 하는데 축이 안 움직임.
- **원인 두 가지** (둘 다 핸들러/config가 사용자의 **새 축 리그**(Right Main/Left Main Weld 구조)를 지원 못 한 것):
  1. `MeleeConfig.Default.ArmWeldMap`이 쓰레받이(handle·brush·body·rubber)를 **팔에 직접 WeldConstraint**로 붙임. 새 축 리그와 충돌해 축을 잠금.
  2. `ClientHandler.setupViewmodel()`의 자동 weld가 "rigged(이미 조인트로 연결됨)" 판정을 **Motor6D만** 검사 → Weld로 축에 붙은 쓰레받이 파트를 "안 붙음"으로 오판하고 **HRP에 재고정**.
- **변경 위치**:
  - `MeleeConfig` Dustpan 항목에 `ArmWeldMap = {}` override(팔 직접 용접 제거).
  - `ClientHandler.setupViewmodel()` rigged 판정에 `Weld`/`WeldConstraint` 포함.
- **검증**(Play): 쓰레받이 파트가 Right Main/Left Main(축)에만 연결됨 확인, 들기·공격·재생·슬라이딩 재생 시 Right Main `Transform` 변화(축 회전) 확인.

## 2. Dustpan 상태별 애니메이션

- **Idle**: 리그 기본 포즈(애니 미재생). 사용자가 리깅한 기본 포즈가 파지 포즈이므로 강제 애니를 얹지 않음.
- **장착**: 들기(70934603796055) 1회 재생 후 기본 복귀.
- **공격**: 좌클릭 스윙에 공격(134776635996855) 연결, **2배속**.
- **달리기 진입**: 재생(71609837264681) 1회 → 1프레임(92638375107608, 무기 내림) 유지. 재생 **1.5배속**(초기 1.8 → 사용자 요청으로 1.5).
- **슬라이딩**: 슬라이딩(81035765089543) 재생 후 마지막 프레임 유지(슬라이딩이 달리기보다 우선).
- **달리기 복귀 규칙**: 슬라이딩 후 복귀(IsRunning 전환) 및 공격 후 달리기 중이면 재생 재적용.
- **변경 위치**: `MeleeConfig` Dustpan 애니 ID, `ClientHandler`의 `AnimMap`/`AnimSettings` + `playRunSeq`/`playSlide` + `startRunWatch`(IsRunning/IsSliding 워처) + `trySwing`(공격 후 재생 복귀).
- **한계**: 지속 달리기·전환 타이밍은 Studio에서 실제 Shift 입력이 막혀(SlideScript가 강제 세팅한 IsRunning을 즉시 되돌림) 라이브 검증 필요. 재생·공격·슬라이딩의 축 이동은 격리 검증됨.

## 3. 근접무기(슬롯3) 이동속도 보너스

- **요구**: 근접무기 장착 시 기본이속 +3, 달리기 +3, 슬라이딩은 비례.
- **로직**(`SlideScript`): `meleeSpeedBonus()` = 장착 Tool에 `MeleeName` 있으면 3, 아니면 0.
  - 걷기/달리기: `targetSpeedFor`의 base에 `+ meleeSpeedBonus()` → 걷기 16→19, 달리기 24→27(맨손 달리기 +3과 동일. Tool 있으면 맨손 +3 로직은 스킵되어 중복 없음).
  - 슬라이딩(비례): `slideSpeed`에 `+ SlideForce × (meleeSpeedBonus/RunSpeed)` = 50×(3/24) ≈ +6.25 (달리기 +12.5%와 동일 비율).
  - 툴 장착/해제 시 `Character.ChildAdded/ChildRemoved`(Tool) 훅으로 이속 즉시 재적용.
- **검증**(Play): 맨손 걷기 16, 근접 장착 걷기 19, 해제 16 확인. 달리기 27·슬라이딩 비례는 실제 달리기 입력 필요로 라이브 검증 대기.

- **검증**(Play): 참가(`InLobby=false`) 시 `Phase` lobby→starting→playing 전이 확인, `workspace.Bots`에 봇 3기(MaxTotal 4 − 플레이어 1) 자동 스폰 확인. 클라 `showAccept`(레디 프롬프트)·`MatchAcceptEvent`·`found`→loadGui 배선은 기존 크로스서버 UI 재사용이라 그대로 동작. **버튼 클릭 체인 자체는 실기(또는 Studio 2인 로컬 테스트)로 최종 확인 권장** — 인서버라 이제 **단일 서버/2인 로컬 테스트로 재현 가능**(크로스서버와 달리).
- **이점/한계**: 수락 시차·재텔레포트·텔포 실패 버그 제거, Studio 재현 가능. 대신 파티(친구 같은 매치 강제)·저동접 시 플레이어 집중 통제력 상실 → 유저·경쟁요소 늘면 매칭 재활성(주석 복원)으로 복귀 가능.

## 8. Dustpan 3인칭 손 모델 — 양손 파지 재구성

- **증상**: 3인칭 애니는 나오는데 손에 쓰레받이 모델이 안 보임 → 강제로 Tool `Handle`(한 손)에 용접했더니 양손 이동 애니와 안 맞고 이상하게 뜸.
- **원인**: 참조 리그 `Workspace.r15 dustpan`은 **양손 파지** — `handle`·`brush`→`Right part`(RightHand Motor6D), `body`·`rubber`→`Left part`(LeftHand Motor6D). 단일 Handle 용접은 틀림.
- **변경**: `Tool.WorldModel`을 리그 구조로 재구성(6파트 + 웰드, 리그 C0 그대로). `Dustpan.ServerHandler`가 장착 시 `Right/Left part`를 캐릭터 양손에 `Motor6D`로 부착(`attach3P`)·해제 시 정리(`detach3P`). 서버 부착이라 전원 복제.
- **검증**(Play): RightHand→Right part / LeftHand→Left part Motor6D 확인, handle/brush 오른손·body/rubber 왼손 근처(0.6~1.7 stud) 추적.

## 9. UI — 킬 히트마커 + 히트마커 크기

- **히트마커 동작·보안**: `HitFeedbackEvent`는 전부 서버 `FireClient`(공격자에게만)만 존재, `OnServerEvent` 없음 → 클라가 조작 불가(cosmetic·서버 구동). 쉴드/HP 어느 쪽 깎여도 `finalDmg>0`이면 뜸(완전 방패 블록만 예외).
- **킬 마커**: 처치 시 히트마커를 **빨강·크게·조금 오래**. 서버 `CapturePointSystem.onDeath` 플레이어 킬 확정 1곳에서 `KillMarkerEvent:FireClient(killer)` → 모든 무기·상대 자동 커버. 클라 `DamageNumbers.showHitMarker(headshot, kill)` 확장. 크기: 기본 12×2 → **36×6**, 킬 60×9(사용자 요청 1.5배).

## 10. 매칭 — 매치 후 재-PLAY 안 잡힘(셀프힐)

- **증상**: 매치 끝→로비→재-PLAY 시 "검색 중"만 뜨고 안 잡힘.
- **원인**: 매치메이커 리더 로비 서버가 대기 인원을 pending(메모리)에 담은 채 비어서 종료 → 그 큐 항목 유실(RemoveAsync 됨) → 영영 안 잡힘.
- **변경**(`runLobbyMatchmaking`): (1) `#Players==0`이면 리더 선출 스킵(빈 서버 리더 방지), (2) 배정 없이 25초+ 대기 시 큐 재등록 셀프힐(`queueTime`), (3) 매치 성립을 유니크 userId 수 기준으로 + 배치 seen 중복 제거. 클라 `MainMenuController`에 검색 90초+ 자동 리셋. **게시본 실기 재검증 필요**(크로스서버 Studio 재현 불가).

## 11. 첫 레디버튼 + 봇 수/타이밍 + 사망 뷰모델

- **첫 입장자 레디 버튼 안 뜸**: `LoadoutSystem.runLoadoutPhase`가 `LoadoutStartEvent`를 참가자에게 1회만 발사 → 첫 입장자 클라 HUD 초기화 레이스로 놓침. → 초기 5초간 미준비자 재전송 + 늦은 참가자 추가.
- **봇 수 과다·자리 차지**: `ensureBots`가 Phase=starting에서 **플레이어 스폰 전** 실행돼 countPlayers=0 → 봇 4마리(전부) + 플레이어 자리 차지. → BotManager Phase 워처를 **플레이어 스폰 완료 대기 후 `ensureBots`**로. Play 검증: 1명 시 봇3·최근접 201stud.
- **사망 중 무기전환/책 사용 시 뷰모델 잔존**: `ViewmodelCleanup`이 사망 시엔 정리 안 함(캐릭터 교체 시만). → 사망/데스캠 즉시 카메라의 무기 `*VM_Local` + 힐 `Book/Snack_Viewmodel_Local` 강제 정리.

## 12. 봇 — 로프 천장 발사 + 스폰분배 봇회피 + 스턱 워치독 (텔레메트리 분석)

- **로프 천장 발사**: 봇은 `lv.VectorVelocity=(b2-a2).Unit*40` + `MaxForce=huge`로 로프를 타 **끝점 지나쳐도 계속 그 방향(위)으로 6초** → 가파른 로프면 천장까지. 플레이어(`GrappleController`)는 선 투영·클램프해 끝에서 정지. → 봇 sticky를 `dir` 저장 + **끝점으로 감속(`toDest.Unit*min(40,dist*3)`) + 근접/지나침 시 하차**.
- **리스폰 시 봇 옆 스폰**: `SpawnDistributor`가 CharacterAdded 재배치 시 플레이어만 회피·봇 무시 → doRespawn이 봇 피한 걸 다시 봇 옆으로. → `nearestBotDist` 추가, 봇도 회피.
- **스폰 정체(안 움직임) — 텔레메트리 분석**: DataStore `AIMovement_v1` 12세션 집계 — 봇 평균 idle 30%(Omega 40%), 거점서 먼 2개 스폰(월드 Z≈-235)에서 유독 체류, 봇 사망 6/145이 스폰서. 원인 후보: AI 업데이트가 단일 Heartbeat에서 전 봇 순회 → 한 봇 에러 시 뒤 봇 미갱신 + 먼 스폰 경로 데드락. → 독립 **스턱 워치독**(playing 중 거점 밖 4초+ 정지 봇을 점프+`MoveTo(ZONE)`로 밀어냄). Play: 런타임 에러 없음(단, 이번 세션 3봇은 정상 이동 — 간헐적).
