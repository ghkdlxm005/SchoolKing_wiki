# 2026-08-13 — AI 개발 로그

| 항목 | 값 |

| 개발 항목 | AI 봇 48차 — 전투 중 고지 선점(사다리·양쪽 건물 실사용) |
| 배경 | "사다리 잘 타는지 봐보자" → 등반은 정상인데 실전에서 거의 안 씀. 원인 규명 후 전투 중 고지 사용으로 확장. |

## 1. 문제 확인 — 등반은 되는데 안 쓴다

- **요구**: 봇이 사다리를 잘 타는지 점검.
- **격리 검증**: 봇을 사다리 바닥(Y4)에 두고 상단을 목표로 강제 → **상단 Y12 도달**. 43차 수정(트러스 중심 접근) 정상, 등반 메커니즘 문제 없음.
- **실전 관찰(35~40초)**: Climbing 진입 0~1회. 봇들이 사다리를 사실상 안 씀.
- **원인 두 가지**:
  1. **양쪽 건물 사다리가 후보에서 제외**. 그 사다리들은 거점거리 73~75인데 47차 고지(VANTAGE) 선정 반경이 70이라 전부 빠짐 → 봇은 거점 코앞 리프트(거리 18)만 선택.
  2. **더 근본적 원인**: 47차 고지 선점이 **로밍(수색) 중에만** 발동. 4봇 FFA 난전에선 봇들이 거의 항상 전투 상태라 로밍이 안 떠서 사다리를 고를 기회 자체가 없음. 반경만 넓혀선 빈도가 안 오름.

## 2. 고지 후보 반경 확대 (48차 A)

- `BotManager` 고지 수집 반경 **70→82**, 고지 점거 중 거점 이탈 leash **70→88**.
- 효과: 거점 양쪽 건물 사다리(거점거리 73~75) **4개가 후보에 편입**(반경 70에선 0개였음). 이제 봇이 리프트뿐 아니라 양쪽 건물 사다리도 목표로 잡을 수 있음.

## 3. 전투 중 고지 선점 (48차 B — 핵심)

- **결정**: 사용자 선택 "전투 중 고지 선점 추가" — 스나이퍼가 로밍이 아니라 **교전 중에도** 고지로 올라가 싸우게.
- **로직**(`BotManager` 전투 포지셔닝 Spot A, 유효거리 계산 직후):
  - 대상: `BotHigh`(스나이퍼) 봇, `#VANTAGES>0`.
  - **선점 조건**: 현재 저지대(`hrp.Y < ZONE.Y+6`) & 대상이 유효거리(`dist>_eng`, 즉 코앞에서 러시당하는 상황이 아님) & 쿨다운 경과 & 확률 0.5.
  - **고지 선택**: 근처(<62) VANTAGES 중 **대상에게 시야 확보되는 곳 우선**(레이캐스트로 top→대상 차폐 검사, 확보 시 45점 가산) → 가장 점수 낮은(가깝고 시야 좋은) 곳.
  - **등반**: 선택 후 `st.combatHigh` 세팅, `followPath`로 고지까지 등반(사다리·리프트 경유).
  - **종료**: 고지 도달(`Y>=ZONE.Y+6`) 시 선점 해제 → 그 위에서 일반 교전(카이팅·스트레이프) / 10~14초 만료 시 해제 + 쿨다운(재등반 방지).
- **왜 이렇게**: 코앞 러시(`dist<=_eng`)엔 등반 금지(전투 이탈로 소극적으로 보이는 것 방지). 스나이퍼는 원래 거리를 벌리는 역할이라 원거리 교전 시에만 고지로 올라감.

## 4. 검증

- **격리**: 스나이퍼 봇 저지대(거점+3) + 원거리 적 → 건물 고지(**거점+12**) 등반 성공.
- **실전(45초·4봇)**: 봇별 **고지 체류 11%·26%·21%**(48차 이전 사실상 0%). 봇들이 실제로 양쪽 건물 위에서 교전. 전투 이탈 과다·에러 0.
- Climbing 상태 진입 카운트는 여전히 낮게 잡히나(0.5초 샘플링이 빠른 등반·리프트/점프대를 놓침), **고지 체류 시간**이 실사용의 실질 지표 — 유의미하게 상승.

## 5. 매칭 수락 시차 → 뒤 사람 갇힘 (텔레포트 실패 복구)

- **증상**: 매칭 수락(accept)을 두 사람이 시차로 누르면, **나중에 누른 사람이 로딩 화면에 갇혀** 매치 서버로 못 들어감(동시에 눌러야만 같이 들어감). 게시 서버 전용이라 Studio 재현 불가 — 코드 분석으로 원인 규명.
- **원인**: 수락 흐름이 `state="found"`를 클라에 보내 **로딩 로고를 먼저 띄운 뒤** `TeleportToPrivateServer`를 호출하는데, 클라이언트에 **`TeleportInitFailed` 핸들러가 없었음**. 텔레포트가 비동기로 실패하면(예약 서버 진입 실패·레이트리밋 — 시차/두 번째 텔레포트에서 더 잦음) 로딩 화면이 영원히 안 꺼지고 갇힘. 기존 18초 anti-stuck 워치독은 `acceptGui`가 켜져 있을 때만 동작 → "found" 이후엔 acceptGui가 꺼져 있어 무력. 서버도 텔레포트 **1회만** 시도(비동기 실패 시 재시도·통지 없음).
- **수정**:
  - **클라(`MainMenuController`)**: `TeleportService.TeleportInitFailed` 핸들러 추가 — 실패 시 수락·로딩·검색 UI 강제 해제 + 로비 복귀 + 재PLAY 안내. 추가로 **로딩 로고 22초 타임아웃 워치독**(카운트다운·텔레포트 없이 로딩만 지속되면 조용한 실패로 보고 복구).
  - **서버(`MatchmakingService`)**: `TeleportToPrivateServer` → `TeleportAsync`(ReservedServerAccessCode)로 교체하고, 모듈 레벨 `TeleportService.TeleportInitFailed`에서 **최대 3회 재시도**(1.5초 간격), 최종 실패 시 클라에 `cancelled` 통지(재큐잉 가능).
- **검증**: 두 스크립트 문법·초기화 정상, 일반 Play 흐름(매치 시작·언프리즈) 회귀 없음, 에러 0. **크로스서버 수락은 게시 서버 전용 → 2인 실기 재검증 필요**(Studio는 로컬 폴백이라 수락 단계 미사용).

## 6. 학습 데이터 점검 — 중앙 쏠림 정량 확인

- **동기**: "봇들이 거점을 중앙 단일 동선으로만 와서, 같이 죽으면 뭉쳐 뛰어오다 몰려 싸운다."
- **DataStore `AIMovement_v1` 집계**(최근 27세션, 총 루트 405·사망 470):
  - 루트 중간점 상위 6개 셀이 전부 거점 반경 2셀(≈48스터드) 안 → **상위 6셀이 전체 이동의 약 59%**. 사망도 거점 셀 11% 최고, 상위 6개 전부 거점 주변. **중앙 쏠림·중앙 몰살** 수치 확인.
  - **결정적**: 405개 루트가 **전부 플레이어 것(봇 0개)**, 그 플레이어 루트마저 중앙 쏠림. 즉 "60% 학습 루트 재생"은 봇을 똑같은 중앙 동선으로 보냄. **학습으로는 동선 분산 불가**(소스가 단일 방향). 봇 자기 동선은 기록조차 안 됨.
- **결론**: 학습에 기대지 말고 **절차적 분산**으로. 사용자 선택 = "측면/건물 경유 중심".

## 7. 측면/건물 경유 접근 분산 (49차)

- **로직**(`BotManager`):
  - **APPROACH 스테이징 지점** 빌드(매치 시작 `task.defer`): ① 거점 28~95 내 수직연결 베이스(사다리·리프트 = 건물 입구), ② 거점 둘레 8방위 radius 50 지면 유효점(레이캐스트). → 거점을 둘러싼 진입 지점 세트.
  - **레인 배정**: 접근 중(거점 55+ 거리) 봇에게 전역 회전 인덱스로 서로 다른 스테이징 지점 배정(`st.appPt`), 스테이징 도달(11) 시 해제 후 거점행. 거점 55 이내면 스테이징 무시(진입 지연 방지). **학습 루트보다 우선**(중앙 쏠림 학습 루트 무력화).
- **검증**(Play 40초 자연 플레이): flank 지면유효 **8/8**, 접근 중 **점유 방위 8/8**(이전엔 중앙 1~2방위 쏠림), **접근 중 봇 간 평균 최근접 거리 76스터드**(뭉침 해소). 에러 0.
- **미해결/후속**: 표본이 아직 작음(실기 다인전에서 재확인). 뭉침이 남으면 경량 분리(separation) 넛지 추가 여지. 스테이징이 너무 우회로 느껴지면 radius/해제거리 조정.

## 8. 리프트/로프 탐지 확장 + 봇 킬 2초 킬캠

- **수직연결 탐지 중첩 허용**: 리프트·사다리·점프대 스캔을 `GetChildren()`→`GetDescendants()`로. 측면 건물 안에 묶어 넣은 리프트(`Lift`)도 인식. (사용자가 측면 건물에 리프트 배치 예정.)
- **`Rope_act` 포함**: 로프/집라인 트러스(`Rope_act` TrussPart)를 VERTS에 사다리 유형(트러스 중심 접근·자동 등반)으로 등록 → 접근 스테이징·고지·수직 추격에 사용. 검증: 2개(높이 54·top Y64) 감지.
- **봇에게 죽어도 2초 킬캠**: `DeathCamController`의 데스캠 렌더가 쓰는 `killerTargetPos()`가 **플레이어 킬러(killerId)만** 처리 → 봇 킬러(killerBot)일 땐 nil 반환으로 킬캠을 건너뛰고 고정 데스캠으로 직행하던 문제(서버는 killerBot 정상 전송 중, `getTargetPos()`엔 봇 분기가 있었으나 렌더 루프는 `killerTargetPos()` 사용). 봇 킬러 분기 추가. 검증: 봇 사망 후 2초 카메라가 킬러 봇 정면 응시(dot 0.98).
